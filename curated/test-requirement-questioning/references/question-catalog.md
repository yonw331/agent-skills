# 三层追问目录

## 业务落地问题

- 谁使用，在哪个业务场景使用？
- 从哪里进入，前置单据、数据、权限和设备条件是什么？
- 操作员、系统、设备、外部系统分别执行什么动作？
- 成功的业务结果是什么，如何被用户和系统观察？
- 实物位置、库存、业务单据和任务如何变化？
- 异常是可忽略、可重试、需暂停恢复、需取消，还是必须人工处理？
- 恢复后从原步骤继续，还是重新开始？
- 放弃、取消、拒绝和失败是否有不同含义？
- 原流程是否保持不变，哪些明确不在本次范围？

## 规格与架构问题

- 哪些页面、接口、服务、任务和数据对象发生变化？
- 哪些既有链路复用，哪些链路新增或分流？
- 规则、算法、排序和容量计算的输入、边界和优先级是什么？
- 状态有哪些，状态转换由什么动作或回调触发？
- 失败、超时、重试和补偿如何保证不产生半成功数据？
- 重复提交、重复回调和并发操作的唯一性如何保证？
- 外部系统状态如何映射，状态缺失或回调乱序如何处理？
- 哪些数据必须保留来源、审计和历史，哪些数据允许合并？
- 高风险实现点位于哪里，如何观察和验证？

## 测试方式问题

- 哪些行为必须在页面和真实操作上手工验证？
- 哪些规则组合应由接口或单元测试覆盖？
- 哪些链路必须跨模块端到端验证？
- 哪些风险需要构造并发、重试、超时或重复回调？
- 哪些场景需要查任务、库存、日志或外部系统证据？
- 哪些手工步骤稳定且高频，适合后续自动化？
- 当前环境有哪些无法执行的场景，遗留风险是什么？
